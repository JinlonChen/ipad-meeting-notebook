# iPad 会议本实时转写设计

## 目标

会议录音期间在 iPad 页面实时显示文字。录音继续按现有方式分片保存在本机并上传；会议转写和会议笔记永久保存；AI 总结不自动运行，只在用户点击“生成 AI 总结”后执行。

## 已确定方案

使用 Supabase Edge Function 作为 WebSocket 中转，连接阿里云百炼 `qwen3-asr-flash-realtime`。浏览器不直连阿里云，因为浏览器 WebSocket 不能安全携带阿里要求的鉴权头，而且直连会暴露 API Key。暂不增加独立服务器，避免额外部署和运维。

阿里实时连接使用用户现有北京地域工作空间：

`wss://llm-gctiyfgr4e625ujt.cn-beijing.maas.aliyuncs.com/api-ws/v1/realtime?model=qwen3-asr-flash-realtime`

设置页继续保留转写和总结两套配置。转写模型固定校验为实时模型，密钥只保存在 Supabase 服务端，不下发到 iPad。

## 组件边界

### 浏览器录音

现有 `MediaRecorder` 路径保持不变，负责可恢复的录音分片和两天后清理。同时从同一个麦克风流接入 Web Audio，把音频转换成 PCM16、16 kHz、单声道小帧，仅用于实时转写。

### 实时转写会话

新增前端实时转写客户端，负责连接、发送 PCM、接收阿里的临时与最终转写事件，以及显示连接状态。临时句只更新页面；最终句通过中转函数写入 `meeting_transcript_segments`，并回传给页面。每条最终句使用稳定标识，重连后重复事件不会生成重复记录。

### WebSocket 中转

新增 Supabase Edge Function。浏览器用当前 Supabase 登录令牌建立连接；函数在连接建立时自行验证用户、会议归属和 AI 配置，然后用服务端保存的 API Key 连接阿里。中转只允许该用户操作自己的会议，不把密钥返回浏览器。

### AI 总结

现有“转写与纪要”合并处理拆开。页面提供独立的“生成 AI 总结”按钮；服务端直接读取该会议已保存的最终转写，调用总结模型，再覆盖保存会议纪要。停止录音不会自动生成总结。

## 数据流

1. 用户点击开始录音，现有本地录音和实时转写同时启动。
2. iPad 将 PCM 音频帧发送到 Supabase 中转，中转转发给阿里实时 ASR。
3. 临时文字立即显示；最终文字由服务端按顺序写入数据库并显示。
4. 用户停止录音，本地录音照常结束、保存和上传，实时转写连接正常关闭。
5. 用户需要纪要时点击“生成 AI 总结”，服务端仅根据已保存转写生成总结。

## 离线与异常

- 断网不停止本地录音，页面显示“实时转写已暂停”。
- 恢复网络后自动建立新会话，继续转写之后的声音。
- 离线期间缺失的文字不伪造；会议结束后可用已上传录音执行补转写，作为后续恢复路径。
- 中转或阿里连接失败不会导致录音失败，实时转写和录音采用独立错误状态。
- 页面切后台、锁屏或 Safari 中断时沿用现有录音恢复机制，已经保存的音频和最终转写不丢失。

## 界面

录音控制区显示实时转写状态：连接中、实时转写中、已暂停、连接失败。转写区在录音时持续展示临时句和最终句；结束后保留最终句。原“生成转写与纪要”改为“生成 AI 总结”，不再让用户重复选择转写动作。

## 验证

- 单元测试覆盖 PCM 转换、阿里事件解析、最终句去重、连接状态和总结按钮行为。
- Edge Function 测试覆盖登录校验、会议归属、配置读取、阿里事件转发与最终句入库。
- 桌面浏览器验证录音、实时文字、手动总结和断网恢复。
- iPad Safari 最终验证一场在线会议，以及一次录音中断网再恢复的会议。
