# 说话人分段与手写会议工作区设计

> 日期：2026-08-25
> 状态：已确认
> 范围：实时说话人分段、可调上下分屏、Apple Pencil 手写、键盘笔记与 AI 总结整合

## 1. 目标

将现有会议详情页改造成适合 iPad mini 6 长时间开会使用的会议工作区：录音时，上半屏在固定区域内持续显示实时转写，并按“发言人 1、发言人 2、发言人 3……”组织段落；下半屏在手写、键盘笔记和 AI 总结之间切换。手写笔迹离线可用、重开可恢复，并在联网后同步到 Supabase 永久保存。

本期以核心会议体验为第一优先级，不加入个人知识库、阅读、共享协作、真实姓名识别或手写文字识别。现有录音 48 小时自动删除规则不变；转写、键盘笔记、AI 总结和手写笔迹永久保存。

## 2. 已选方案

### 2.1 说话人识别

考虑过三种实现：

1. **阿里实时 Recognition API 原生说话人分离（选定）**：使用支持 `diarization_enabled` 和 `speaker_count` 的官方 DashScope SDK，在现有 Mac 中继中完成识别。实时性最好，不向浏览器暴露 API Key，也能沿用现有 WebSocket 鉴权。
2. **继续使用当前实时模型并按停顿猜测说话人**：无需换模型，但停顿不能代表换人，无法满足三人会议验收要求。
3. **会议结束后仅做整段离线识别**：说话人结果可能更稳定，但会议中看不到带标签的实时转写，不符合目标。

实施必须先完成一个独立的 30 秒真实音频冒烟测试。只有当 Recognition API 能用现有阿里 Key 返回中文文本、时间信息和至少两个不同 `speaker_id` 时，才允许替换当前实时链路。测试不把 Key 写入仓库、日志或命令历史。当前 `qwen3-asr-flash-realtime` 保留为运行时降级提供方。

### 2.2 工作区布局

采用已确认的 B 型布局：顶部是固定高度范围内可滚动的转写区，底部是带标签页的工作区，中间分隔线可拖动。标签页为“手写 / 键盘 / AI 总结”，默认打开“手写”。这比把三块内容纵向堆叠更适合 iPad mini 6，也能保证转写更新不会推动手写画布跳动。

### 2.3 手写存储

手写以矢量笔画保存，不保存画布截图。每条完成的笔画独立持久化，点序列包含坐标、压力和时间；撤销或橡皮操作用删除标记同步。与每次保存整张大 JSON 相比，按笔画增量保存能减少离线写入和云同步的数据量，也避免一次同步失败导致整页笔记无法保存。

## 3. 页面结构与交互

会议工作区从上到下包含：

- 顶栏：返回、会议标题和统一保存/同步状态。
- 会议信息与录音栏：会议状态、分类、更新时间、录音按钮、计时、转写连接状态和预计发言人数。
- 转写区：占工作区可用高度的 30%–70%，默认 45%，内部独立滚动。
- 可拖动分隔线：仅调整转写区与下方工作区的比例，不影响顶栏和录音栏。
- 下方工作区：固定标签栏和当前标签内容。

分屏比例保存在本机，重开应用后恢复；横竖屏分别记忆，避免旋转后得到不合适的高度。拖动时设置最小高度，任何方向都必须能看到至少三行转写和一行完整工具栏。控件、文字和同步状态在 iPad mini 6 横竖屏中不得重叠或被省略成无法理解的“……”文本。

### 3.1 转写区

- 每段显示开始时间、说话人标签和正文。
- 当前未最终确认的文本显示在列表底部，并使用临时说话人标签；最终事件到达后原位更新，不闪烁新增重复行。
- 同一说话人连续发言时，将新句追加到当前段并延长结束时间；中间出现其他说话人后，即使原说话人再次发言，也创建新段。
- 正常状态自动跟随最新内容。用户主动向上滚动超过阈值后暂停自动跟随，并显示“回到最新”按钮；点击后恢复自动跟随。
- 没有转写时显示安静的空状态。识别暂停或降级时在转写区顶部显示短状态，不遮挡已有内容。

### 3.2 预计发言人数

录音开始前提供“自动、1、2、3、4、5、6+”选项，默认“自动”。选择结果按会议保存在本机，开始录音时随 WebSocket 鉴权消息发送给中继；录音中锁定，停止后可修改。`1`–`5` 直接作为 `speaker_count`，`6+` 不传精确人数并让模型自动判断，避免错误约束识别。

### 3.3 下方标签页

- **手写**：默认标签。包含笔、荧光笔、颜色色板、粗细控制、橡皮、撤销和重做。
- **键盘**：复用现有纯文本会议笔记和离线同步逻辑，不改变 200,000 字符上限。
- **AI 总结**：显示生成按钮、状态和结构化纪要。总结输入包含最终转写和键盘笔记，不读取手写内容。

切换标签不会销毁任何编辑状态。录音、实时转写和自动保存不因标签切换而停止。

## 4. 实时说话人数据流

### 4.1 会话建立

1. 浏览器继续从录音使用的同一麦克风流生成 16 kHz、16-bit、单声道 PCM。
2. 浏览器连接现有中继 WebSocket，发送 Supabase access token 和可选预计人数。
3. 中继验证来源、用户和会议所有权，从 Supabase 服务端读取已有阿里语音 Key。
4. 中继优先启动 DashScope Recognition 提供方，并启用说话人分离；启动失败时立即切换到当前 Qwen 实时提供方。
5. 浏览器收到 `ready` 后开始发送音频。识别失败不得停止 MediaRecorder，也不得删除或阻塞本地录音分片。

### 4.2 标签和合并规则

阿里返回的原始 `speaker_id` 只在服务端使用。中继按本次识别会话中首次出现顺序映射为“发言人 1、发言人 2……”：

- 第一个未见过的 ID 映射为“发言人 1”，第二个映射为“发言人 2”，依此类推。
- 相邻最终句映射到同一标签时，更新上一条持久化段落的正文和结束时间，不新增 `position`。
- 标签变化时，新建下一条段落。
- 文本拼接根据中英文标点决定是否补空格，禁止直接无分隔拼接英文单词。
- 重复的提供方事件必须幂等，不能造成重复文字或跳号。

中继向浏览器发送统一的 `segment-upsert` 消息。新段和同一段的后续更新都使用同一段落 ID；浏览器按 ID 替换，Supabase 也按用户和段落 ID 更新。现有只追加 `final` 的协议保留兼容解析，便于逐步部署中继和网页。

### 4.3 会后校正

停止录音时，浏览器先通知中继结束输入，中继要求当前 Recognition 会话完成并在有限等待时间内接收最终结果。随后对本次会话执行一次确定性校正：

- 用最终 `speaker_id` 覆盖临时标签；
- 按首次出现顺序重新编号，保证标签连续；
- 合并校正后相邻且说话人相同的段；
- 重新生成连续 `position`，并在一个服务端事务中替换本次会话产生的段落；
- 向浏览器发送 `transcript-reconciled`，触发一次完整刷新。

第一版会后校正使用同一次实时 Recognition 会话的最终结果，不识别真实姓名，也不另行调用声纹或整段离线模型。正常联网、单次识别会话不中断是“三人标签稳定”验收的前提。网络中断后恢复时，新会话的说话人标签属于临时结果；已有录音仍完整保存，普通转写恢复后继续。未来如果实测需要跨会话统一身份，再单独增加整段音频的批量说话人重分离，不混入本期。

### 4.4 降级

- Recognition 启动失败：同一中继连接切到现有 Qwen 实时模型，继续输出不带说话人标签的转写。
- Recognition 运行中只缺少 `speaker_id`：保留文本并显示“未区分发言人”，不丢弃句子。
- 实时提供方完全失败：录音继续，本地显示“实时转写暂不可用”。
- 浏览器离线：录音继续保存在本机；恢复网络后重连实时转写。第一版本不把离线期间音频补传做实时转写。
- 持久化失败：停止发送新的已确认段，保留录音，并向界面显示可重试错误，避免界面显示了实际上未保存的最终文本。

## 5. 手写模型与渲染

### 5.1 输入与坐标

手写组件使用 Pointer Events 接收 Apple Pencil。每条笔画保存：

- 全局唯一 `strokeId`、`meetingId` 和创建顺序；
- 工具类型 `pen` 或 `highlighter`；
- 颜色、基础粗细；
- 点序列 `{ x, y, pressure, elapsedMs }`；
- 删除状态和更新时间。

坐标使用固定逻辑宽度并按显示宽度等比渲染，避免分屏拖动或横竖屏切换后笔迹错位。逻辑画布纵向可增长；接近底部时增加书写空间。Apple Pencil 压力调节笔的实际线宽，荧光笔使用固定透明度。无压力信息时使用基础粗细，保证鼠标和手指测试可用。

画布用高分辨率 Canvas 渲染以保证 iPad 性能，但持久化内容始终是矢量点序列。设备像素比变化、重开页面或导出时都从矢量数据重绘，不能读取 Canvas 位图作为主数据。

### 5.2 工具行为

- 笔和荧光笔使用最近一次选中的颜色与粗细。
- 橡皮采用整笔擦除：命中一条笔画即把该笔画标记删除，避免局部切割产生大量碎片。
- 撤销和重做只作用于当前设备尚可追踪的最近操作，包含新增笔画和擦除；产生新操作后清空重做栈。
- 单指在非书写状态下用于滚动画布；Apple Pencil 用于书写。工具栏按钮使用图标、选中态和可读提示。
- 页面转入后台、切换标签或返回会议列表前，立即提交当前正在写的笔画。

## 6. 手写离线存储与云同步

### 6.1 IndexedDB

新增独立的手写数据库或对象仓库，按 `userId + meetingId + strokeId` 保存笔画。每条完成的笔画先事务写入 IndexedDB，成功后才显示“已保存到本机”；删除、撤销和重做同样先写本地。待同步队列按笔画 ID 合并，同一笔画多次变化只保留最新操作。

重开会议时先从 IndexedDB 恢复并立即绘制，不等待网络。退出登录时沿用现有按用户隔离规则，不能把一个账户的笔迹展示给另一个账户。

### 6.2 Supabase

新增 `meeting_ink_strokes` 表，主键为 `user_id + id`，并以 `user_id + meeting_id` 索引。字段保存工具、颜色、粗细、点序列、创建顺序、删除时间和服务端更新时间。表通过会议复合外键绑定所有者，启用 RLS；浏览器只允许读取自己的行，写入经严格校验的 authenticated RPC 完成。

每条同步操作带全局唯一的 `mutationId`。服务端按笔画 ID 串行、幂等 upsert，不使用可能不准确的客户端时钟判断先后：

- 不同笔画天然合并；
- 同一笔画以后被服务端接受的操作为准，重复的 `mutationId` 直接返回既有结果；
- 删除使用 tombstone，不物理删除，以免离线旧设备把已擦除笔画重新上传；
- 云端成功后清除对应本地待同步操作。

笔迹正文、坐标和 API Key 不写日志。服务端限制单条笔画点数、JSON 大小、颜色格式、粗细范围和会议所有权；超过上限时本地结束当前笔画并开启下一条，用户视觉上仍是一条连续线。

### 6.3 冲突与失败

手写采用按笔画合并，不提供整页“本机版/云端版”冲突对话框。新增笔画不会互相覆盖；同一笔画的擦除、撤销和重做按服务端接收顺序解决。网络失败只保留待同步队列，不影响继续书写。IndexedDB 写入失败时保留当前画面但显示“手写未保存”，暂停开始新笔画并提供重试，避免让用户误以为数据已经持久化。多台设备同时修改同一笔画不属于本期优化目标。

## 7. AI 总结调整

AI 总结按钮不再与实时转写并排，而放在下方“AI 总结”标签中。生成时服务端读取最终转写段和会议键盘笔记，并明确标注两种来源后发送给现有总结模型。手写笔迹本期完全排除，不上传图片，也不做 OCR。

只要最终转写或键盘笔记至少一项非空，且网络、登录和总结配置有效，就允许生成总结。说话人标签可作为上下文传给总结模型；没有标签时按普通文本处理。重新生成覆盖该会议上一版 AI 总结，现有证据段 ID 仍只引用转写段，不为键盘笔记伪造证据 ID。

## 8. 模块边界

- `services/transcription-relay`：DashScope Recognition 适配、提供方降级、说话人映射、连续段合并和会后校正。
- `apps/web/src/transcription`：WebSocket 协议、临时/最终段状态、重连和转写滚动数据源。
- `apps/web/src/ink`：Pointer Events、笔画建模、Canvas 渲染、工具状态、IndexedDB 仓库和同步队列。
- `apps/web/src/meetings`：分屏布局、标签切换、预计人数和统一保存状态。
- `apps/web/src/intelligence`：转写展示、AI 总结触发和结果展示；不直接管理录音或手写存储。
- `packages/contracts`：转写事件、说话人字段、笔画和同步载荷的共享验证规则。
- `supabase`：笔画表/RPC、转写段更新与会后替换事务、AI 总结读取键盘笔记。

这些模块通过显式端口和数据契约连接，避免继续扩大 `MeetingWorkspacePage.tsx` 和 `MeetingIntelligencePanel.tsx`。页面只编排组件，不直接实现笔迹算法或说话人合并。

## 9. 测试与实施顺序

实施按以下门槛推进：

1. **30 秒阿里冒烟测试**：使用真实两人以上轮流说话音频，确认中文、时间和不同 `speaker_id`。失败则停止说话人替换工作，保留当前模型并报告准确错误。
2. **中继单元与集成测试**：覆盖 ID 映射、同人连续合并、换人新段、重复事件、预计人数、结束校正和 Qwen 降级。
3. **手写模型测试**：覆盖压力宽度、点序列上限、整笔擦除、撤销/重做、逻辑坐标缩放和重绘。
4. **离线与同步测试**：覆盖断网写入、关闭重开、队列合并、tombstone、联网恢复和账户隔离。
5. **工作区组件测试**：覆盖拖动边界、比例记忆、标签状态保留、自动滚动暂停及“回到最新”。
6. **全量自动验证**：运行测试、类型检查、构建和前端产物密钥扫描。
7. **iPad mini 6 实机验收**：完成三人轮流发言、同人连续发言合并、手写断网保存、关闭重开恢复、联网同步和 AI 总结。

实机验收时还要分别检查横屏和竖屏：录音按钮、计时、预计人数、转写、分隔线、手写工具栏和同步状态均可见且不重叠。浏览器刷新和从主屏幕重开后，分屏比例、键盘笔记和手写笔迹均恢复。

## 10. 安全与运维

- 阿里 Key、Supabase service-role key 继续只保存在服务端，网页构建产物不得包含它们。
- WebSocket 继续校验允许来源、Supabase token、会议所有权、单用户单会议并发、消息大小、空闲和最长会话时间。
- 说话人识别与手写同步错误只记录错误码和不含内容的标识，不记录音频、转写正文或笔迹点。
- Quick Tunnel 地址变化的现有限制不在本期解决；实施和部署期间保持当前 Mac 中继运行。

## 11. 验收标准

- 正常联网的三人会议中，实时转写显示“发言人 1、2、3”；同一人连续说话只占一段，换人后才新建段。
- 预计人数为“自动”或手动值时均能开始录音；模型不支持或识别失败时，录音和普通转写继续。
- 转写只在上半区滚动，用户上滚后不会被新内容拉回，点击“回到最新”恢复跟随。
- 分隔线可在限制范围内拖动，横竖屏比例分别记忆，页面无重叠或截断。
- Apple Pencil 压感、笔、荧光笔、颜色、粗细、整笔橡皮、撤销和重做可用。
- 断网手写后关闭并重开，笔迹仍存在；联网后自动同步，另一已登录页面能够恢复云端笔迹。
- 录音停止后完成一次最终说话人校正，已有段落不重复、不丢字、位置连续。
- AI 总结使用转写和键盘笔记，会议结束后或用户需要时可生成；手写内容不进入总结。
- 原始录音仍按 48 小时删除，会议、转写、键盘笔记、AI 总结和手写笔迹不会随之删除。

## 12. 非目标与未来迁移

本期不做真实姓名、声纹注册、手写 OCR、手写搜索、PDF 导出、多人协作、跨会议知识库或阅读功能，也不补转离线期间缺失的实时转写。

未来 NAS 上线后可以迁移：网页静态文件、中继服务、数据库、对象存储和定时清理都保持清晰边界。迁移前可先把 Mac 中继容器移到 NAS，同时继续使用 Supabase；之后再按导出、校验、切换和回滚步骤迁移数据库与音频存储。NAS 迁移不属于本期实施和验收范围。
